## Evidence contract

- Each substantial theory sequence has three deliberately different formative checks: essential recall, concept link and likely misconception. This is a teaching design, not a quota generator.
- Every option has answer-specific explanatory feedback. Pre-submit hints remain answer-neutral and point to the exact Stage 05 block anchor.
- Each sequence ends with one substantial, scaffolded written application labelled **Formative learning evidence**.
- Saved check, activity and capstone records are browser-local. The UI must say **Saved on this device** and must never imply cloud sync, formal assessment, submission, teacher observation or a competency decision.
- Stage 13 should include each capstone in the printable/exportable course formative-evidence summary and reset only the selected record after confirmation.

## Integration and test requirements

1. Render each theory block with its exact `id`; help links must focus and scroll to that target without exposing the correct option before submission.
2. After submission, show feedback belonging to the selected option and a link to that option's check-level `helpAnchor`.
3. Save each check independently; reload must restore its completed/revisit state without changing other sections.
4. Save every capstone while typing, show the local-only notice, and include it in print/export with its section title and saved timestamp.
5. An isolated reset may remove only the selected check or capstone key after confirmation.
6. Keyboard, touch, print/export and exact 390 CSS pixel tests remain Stage 13 integration responsibilities because this artifact contains data only.
